# Reports

## 1. Purpose

**Question:** How do I mix the right frozen project story for this audience without changing the underlying truth?

## 2. Why it is powerful

Reports separates facts from presentation. Audience and purpose choose a module recipe; the report freezes source-aware owner facts, caveats, and an optional clearly labeled operator note.

## 3. Mental model

The composer is a rack. Modules are lenses over the same immutable read model. Reordering, enabling, or changing density changes communication—not Reality. Creating a report is like taking a signed photograph of the model.

## 4. Truth / ownership boundary

Reports owns immutable snapshots, recipe, audience, purpose, mode, comparison pointer, and presentation-only note/promoted asks. Owner facts remain owned by Forecast, Decisions, Dependencies, Scope, Capacity, Timeline, Audit, and ContextSnapshot.

## 5. Inputs

Report-ready live Reality or explicit Scenario; forecast coverage/currentness; target/commitment; Decisions/gates; Dependencies; Scope/work; Capacity contract; Timeline; Audit delta; evidence/source health; prior reports.

## 6. Outputs

Immutable audience brief, print view, plain-text copy with provenance, history entry, and interactive Site handoff bundle where offered.

## 7. Screen tour

| Area | Meaning / control |
|---|---|
| Project selector | Report subject |
| Audience | Operator/PO, Delivery Leadership, Executive, Stakeholder/Partner, Portfolio/Staffing, Decision/Scenario |
| Purpose | Weekly Update, Delivery Review, Steering Committee, Launch Readiness, Decision Meeting, Scenario Review, Handoff, Executive Update |
| Mode | Reality or explicit Scenario snapshot |
| Module rack | Enabled modules and order |
| Module density | Headline/compact/expanded where supported |
| Operator note | Presentation-authored context, labeled and never merged with facts |
| Leadership asks | Only operator-promoted Decisions; candidates stay candidates |
| Preview | Current recipe over frozen owner facts |
| Create report | Stores immutable snapshot/recipe |
| Copy plain text | Includes historical provenance for stored reports |
| Print view | Stable rendering of selected snapshot |
| History | Reality/Scenario, audience, generated time, legacy/snapshot semantics |
| Site handoff | Prepares an interactive governed bundle; user-mediated publication |

## 8. Primary happy path

1. Start at Audit → Report Readiness.
2. Clear or understand every blocker.
3. Open Reports and select project.
4. Choose audience, then purpose.
5. Inspect proposed modules; reorder or change density only for comprehension.
6. Add an operator note only when the audience needs context not owned elsewhere.
7. Verify likely, target, commitment, coverage, currentness, and mode.
8. Create report.
9. Re-open history, confirm generated-at/provenance, then copy/print/share.

## 9. Secondary journeys

- Compare to a prior report for movement.
- Build Executive or Portfolio/Staffing variants from the same frozen facts.
- Create a Decision/Scenario brief with explicit hypothetical mode.
- Use Site handoff when the control is live and the destination workflow is ready.

## 10. Writes / side effects

Creating a report stores an immutable snapshot and recipe. It does not alter owners. Copy/print are outbound representations; validate the selected historical/live context first. Site handoff does not silently publish.

## 11. What it does not do

It does not regenerate old reports, turn candidate asks into authority, hide missing inputs, or make a Scenario into Reality. Presentation narrative must be deterministic from frozen facts except the labeled operator note.

## 12. Warnings / empty states

Report Not Ready exposes blockers. Forecast unavailable/incomplete must remain visible. Legacy reports stay retained with a legacy banner. Historical snapshots show generated-at and live delta so copied text is not mistaken for current.

## 13. Handoffs

Audit readiness first; owner instruments to repair inputs; Timeline for commitment; Site workflow after snapshot creation.

## 14. Common mistakes

Starting in Reports; copying an old snapshot; hiding caveats for executives; calling target a commitment; publishing a Scenario without labeling; adding operator prose as if source fact.

## 15. Troubleshooting

If creation is refused, follow readiness/coverage reason. If copied text differs from screen provenance, log immediately. If a module has no supported facts, disable it or preserve its explicit unavailable state.

## 16. Operator checklist

- [ ] Readiness checked
- [ ] Audience/purpose/mode correct
- [ ] Coverage/currentness/caveats visible
- [ ] Likely/target/commitment distinct
- [ ] Generated snapshot re-opened and verified

## 17. Real example

A Delivery Leadership weekly brief leads with delivery outlook, commitment, movement, why this date, acceleration levers, leadership asks, what changed, next, dependencies, source health, and caveats. An Executive brief is shorter but uses the same owner facts.
