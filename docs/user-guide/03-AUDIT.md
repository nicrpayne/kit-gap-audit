# Audit

## 1. Purpose

**Question:** Where does accepted delivery Reality disagree with current evidence and execution?

## 2. Why it is powerful

Audit keeps external intelligence useful without letting it govern. It shows the project as a world of accepted Reality, project structure, source systems, evidence, findings, decisions, and open loops—with provenance available before acceptance.

## 3. Mental model

The center is Reality. Position/category says what an object is about; distance/band says degree of disagreement. Search locates, Inspector explains, Trace isolates provenance or relationships, and the Change Inbox turns new intelligence into explicit owner proposals.

## 4. Truth / ownership boundary

Audit owns Findings, runs, snapshots, change proposals, dispositions, and provenance views. Owner instruments own accepted Scope, Decisions, Dependencies, Capacity, and Timeline. Audit can call an owner-specific acceptance route; it cannot perform a generic “accept into Reality.”

## 5. Inputs

ContextSnapshot, bootstrap/refresh packages, evidence passages, source manifests, current execution, accepted owner truth, companion state, and prior Audit baseline.

## 6. Outputs

Findings; freshness/readiness readings; source health; change proposals; accepted owner mutations with audit trail; links into owner instruments. Forecast and Reports consume the resulting owner state, not an Audit opinion.

## 8. Primary happy path

1. Select the project and read Knowledge state.
2. Refresh only from a completed new state.
3. Open Changes; select one proposal.
4. Compare current and proposed owner states.
5. Inspect relevance, exact evidence, retrieval basis, and forecast-effect description.
6. Accept only if the owner-specific write is complete and correct; otherwise edit, defer, reject, or mark information-only.
7. Use Trace in world for a material finding.
8. Review Source health and Report readiness.

## 9. Secondary journeys

- Search an exact capability or quote; fly to it; inspect its cluster.
- Trace source → passage → finding → Reality.
- Review processed proposals as an audit trail.
- Open `/audit/history` to compare past runs without changing current world.

## 10. Writes / side effects

Refresh creates a new frozen package/snapshot/Audit comparison; it does not edit prior snapshots. Edit changes the proposal only. Accept invokes the named owner mutation and refreshes derived reads. Defer/reject/information-only preserve provenance. Some accepts require explicit completion and confirmation.

## 11. What it does not do

Audit does not certify evidence, infer people, create gates from Decision importance, or create dependencies from semantic relations. A Finding is neither Evidence nor Reality.

## 12. Warnings / empty states

No attached exact passage triggers completion. Cross-scope/neighboring relevance requires judgment. Source-health and capacity categories have no generic Accept. Offline/ingesting states disable refresh to avoid split-brain inputs.

## 13. Handoffs

Scope, Decisions, Dependencies, Timeline, Capacity, source setup, or Reports—use the proposal's owner link.

## 14. Common mistakes

Treating recommended accept as authority; counting derivative pages as independent evidence; confusing radial position with confidence; leaving an active Trace and assuming the rest of the world disappeared.

## 15. Troubleshooting

Check selected project, companion status, package/snapshot ages, and source registration. If a result cannot be seen after search, use fit/expand; that is expected to be automatic and should be logged if not.

## 16. Operator checklist

- [ ] Knowledge state and last package understood
- [ ] Every material proposal dispositioned
- [ ] Evidence/currentness checked
- [ ] Owner consequence understood
- [ ] Source health and readiness checked

## 17. Real example

A JSA meeting says an investigation capability is required. Audit may propose a capability plus an unresolved organizational Decision. Accepting the capability changes Scope; accepting the Decision creates it open and ungated. Only a separately evidenced DecisionGate can move Forecast.
