# Signal Glossary

| Term | Operational meaning | Do not assume |
|---|---|---|
| Accepted | A proposal was written through its canonical owner | That the evidence is new, independent, or complete |
| Actual team | The complete confirmed named roster and allocations | Everyone mentioned in knowledge is staffed |
| Audit | Comparison of external intelligence/execution against accepted Reality | A generic data-import screen |
| Capability | A product-shape object governed by Scope | A ticket or automatically executable work |
| Candidate / proposal | Suggested future owner mutation | Reality |
| Commitment | A canonical commitment state or committed milestone | Target or likely date |
| ContextSnapshot | Frozen package of source-aware project context | Live mutable wiki |
| Currentness | Whether an as-of reading is within its defined horizon | Authority, correctness, or completeness |
| Decision | A choice with lifecycle, options, evidence, owner, and resolution | A delivery gate |
| DecisionGate | Structured serial wait attached to an open Decision and target Scope | Priority or general importance |
| Dependency | Explicit source→target delivery topology | Semantic relationship or neighboring context |
| Derived consequence | Automatic recomputation after inputs change | A separate Reality write |
| Effective FTE | Raw allocation reduced by the shared context-switch factor | Utilization, productivity, or ticket assignment |
| Evidence Passage | Bounded cited excerpt with provenance | Accepted truth |
| Forecast | Monte Carlo consequence of covered execution, capacity, gates, and dependencies | Promise, plan, or manually chosen date |
| Forecastable | Coverage contract supports a canonical delivery forecast | Certainty |
| Grounding | Quality and traceability of supporting passages | Confidence percentage |
| Hermes | Longitudinal intelligence and synthesis layer | Authority to change Signal Reality |
| Historical | Immutable past snapshot or record | Current state |
| Information only | Retained for context without an owner mutation | Rejected or false |
| KE / wiki | Institutional knowledge and synthesized current understanding | Independent primary evidence or delivery truth |
| Likely | Central simulated delivery date | Target or committed date |
| Live | Read from the current owning system | Fresh/current |
| Modeled subset | Valid model of only the covered portion of accepted shape | Full-project forecast |
| Open Decision | Unresolved choice | Automatically blocking delivery |
| Operator note | Clearly authored presentation context in a report recipe | Owner fact |
| Project Activation | Atomic boundary from reviewed dormant knowledge to first governed Reality | Automatic truth ingestion |
| Raw FTE | Sum of named allocations before switching cost | Effective forecast capacity |
| Reality | Current canonical delivery state and live owned inputs | Everything the knowledge system has heard |
| Report Ready | Defined readiness checks pass at that moment | Future freshness or correctness guarantee |
| Scenario | Browser-local hypothetical overlay | Saved Reality |
| Source Health | Provider/configuration/currency facts | Content truth |
| Target | Date against which confidence is evaluated | Likely or commitment |
| Timeline event | Time object owned by Timeline | Forecast mark, Decision, Report, or Linear item |
| Trace | Focused provenance/relationship path | A causal proof when the edge is only inferred |
| Unavailable forecast | Reliable execution input is missing | Zero work or zero duration |
