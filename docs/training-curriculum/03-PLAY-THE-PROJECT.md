# Session 3 — Play the Project

**Duration:** 45 minutes

## Objectives

Reconcile named Capacity; build a one-variable Scenario; interpret cross-project effects; read coverage/uncertainty/target confidence; use Timeline without rewriting history.

## Prerequisites

Sessions 1–2 complete. Use the stable disposable fixture for roster and commit exercises.

## Walkthrough

1. **0–12 min — Capacity contract.** Compare aggregate_unreconciled, named_partial, and named_exact. Open Set actual team and review the complete roster confirmation.
2. **12–25 min — Scenario.** Move one named allocation. Read raw and effective FTE, switching cost, affected projects, and an unchanged project.
3. **25–35 min — Forecast.** Coverage first. Compare Scenario body to Reality ghost, likely date, window, target confidence, and miss tail. Scrub target to prove it does not rerun the model.
4. **35–42 min — Gates/dependencies.** Assume one existing gate resolved; contrast with a capacity change and a dependency propagation.
5. **42–45 min — Timeline.** Press Play; identify historical hold-and-step, NOW, live Forecast, planned milestone, and commitment.

## Exercises

- Explain raw → effective → Forecast FTE.
- Predict which projects move before moving the fader; compare outcome.
- Move target ±7 days and say what did not change.
- Return to Reality and confirm the Scenario marker clears.

## Check questions and expected answers

1. **What makes capacity named exact?** Complete roster confirmation plus reconciled named allocations used exactly by Forecast.
2. **Is effective FTE productivity?** No; it is a modeled capacity input after shared switch cost.
3. **Why might added capacity not move a date?** A serial gate, dependency floor, or other work/constraint dominates.
4. **Does moving target improve the Forecast?** No; it changes the confidence lookup only.
5. **May Timeline resimulate a past date?** Never; historical belief comes from immutable reports.

## Common mistakes

Committing a live what-if; omitting a roster member while confirming complete; leading with a modeled-subset date; interpreting target as model input.

## Hands-on task

Run the named-transfer Scenario in `DEMO-STATE.md`, narrate input change, direct effect, dependency effect, non-effect, and why. Discard and reproduce the baseline exactly.
