# Session 4 — Communicate

**Duration:** 30 minutes

## Objectives

Use Report Readiness; select audience/purpose; preserve likely/target/commitment and live/historical distinctions; create and verify an immutable brief; explain Site handoff.

## Prerequisites

Sessions 1–3 complete. Fixture should be Report Ready with a prior report for comparison.

## Walkthrough

1. **0–7 min — Readiness.** Open Audit → Report Readiness; follow one example blocker to its owner and back.
2. **7–17 min — Composer.** Choose Delivery Leadership + Weekly Update. Review modules, owners, density, order, caveats, and operator note boundary.
3. **17–23 min — Freeze.** Create the fixture report, re-open it from history, and read the generated-at/source provenance.
4. **23–27 min — Variants.** Switch preview to Executive and Portfolio/Staffing; explain that facts do not change.
5. **27–30 min — Handoff.** Show print/plain-text and the user-mediated interactive Site bundle where supported.

## Exercises

- Turn one technical model fact into plain executive language without removing its caveat.
- Identify one module owned by Presentation rather than a project owner.
- Compare an old snapshot with live Forecast.

## Check questions and expected answers

1. **Does Report Ready mean guaranteed correct?** No; defined checks pass at that moment.
2. **Can audience choice change the likely date?** No.
3. **How is authored context represented?** As an explicitly labeled operator note.
4. **What happens when Reality changes after save?** The old report stays historical and immutable.
5. **Does Signal publish the Site automatically?** No; handoff is explicit and user-mediated.

## Common mistakes

Starting in Reports; removing caveats for brevity; copying a historical report without provenance; promoting candidate asks.

## Hands-on task

Create Delivery Leadership and Executive previews from the same fixture truth. Explain every changed presentation choice and confirm no owner fact changed.
