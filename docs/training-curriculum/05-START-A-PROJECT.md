# Session 5 — Start a Project from Nothing

**Duration:** 45 minutes

## Objectives

Create pre-Reality identity; read scan/provider coverage; disposition bootstrap candidates; verify provenance; understand the manifest; activate a disposable project; operate the First Audit.

## Prerequisites

Sessions 1–4 complete. Staging/disposable environment only. Companion online with a prepared bounded knowledge fixture.

## Walkthrough

1. **0–7 min — Identity.** Add project with canonical name, aliases, owner/source hints. Say aloud what is not created.
2. **7–15 min — Scan.** Create & scan; watch pipeline stages, provider coverage, and package census.
3. **15–30 min — Bootstrap Review.** Work each section. Inspect evidence vs derivative passages; accept, defer, reject, and information-only examples.
4. **30–37 min — Manifest.** Compare WILL BECOME CANONICAL with WILL REMAIN EXTERNAL/CANDIDATE. Acknowledge known gaps.
5. **37–42 min — Activate.** Submit only in disposable fixture; verify atomic output and idempotent retry behavior.
6. **42–45 min — First Audit.** Read expected execution/provider/ambiguity gaps and hand off to Scope.

## Exercises

- Explain why review Accept is not Reality.
- Find one derivative-only candidate and decide its safe disposition.
- Predict every row activation will and will not create.
- Explain why Forecast is unavailable immediately after a valid activation.

## Check questions and expected answers

1. **Can Railway scan the local KE path?** No; the local companion compiles and posts a bounded package.
2. **Does accepting a Decision candidate create a gate?** No.
3. **Does a person mention create Person/Allocation?** No.
4. **What happens on activation validation failure?** The serializable transaction rolls back all writes.
5. **Why First Audit?** To surface what accepted Reality still does not represent or cover.

## Common mistakes

Activating with unreviewed pending candidates; counting wiki synthesis as independent evidence; interpreting partial package as failure or completeness; using a real project to practice.

## Hands-on task

Recreate Harbor Relay or the documented Signal Studio fixture, activate it, then produce a spoken handoff: canonical objects created, candidates retained, missing inputs, and exact next owner instrument.
