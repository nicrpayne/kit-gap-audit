# Root-cause ledger

| Symptom | Class | Exact cause/evidence | Resolution |
|---|---|---|---|
| Accepted capability absent on another computer | PRODUCT BUG | `SuiteScenario.draftFeatures` was a module-level client store. Add Capability and release bypasses had no canonical Capability write, despite a server Capability model existing. A second JavaScript realm could never read them. | Governed Capability APIs and owner service now persist accepted composition in PostgreSQL. |
| Browser view could remain behind after another device writes | STALE CACHE | The project read was held in a module store; its revision bus only crosses components in one JavaScript realm. No focus/visibility/interval revalidation covered a write from another machine. | Private/no-store project responses plus focus, visibility, navigation, and 15-second revalidation. |
| Scenario-only change is absent on another device | EXPECTED SCENARIO BEHAVIOR | Scenario is intentionally local and hypothetical until explicit commit. | Strong visual Reality/Scenario labels and an explicit “Commit this draft to Reality” action. |
| JSA expected capability set incomplete | DATA/CONFIG + UX GAP | Linear parent structure was treated as the only product-shape source; unparented tickets were shown only as an undifferentiated gap and manual accepted shape was not operable. | Governed manual capabilities plus a raw unmapped execution tray. |
| New JSA tickets can read as `Linear current · empty` | SOURCE-MAPPING ISSUE (strongest evidence; production row still unverified) | Linear filtering is exact on team/project/optional label. Seed and historical fixtures still name `KIT Safety (JSA and iTrack)` while current repository/runbook authority names `KIT JSA`. Exact matching against the stale project returns zero. The implementation has no created/updated cutoff. | UI and server keep current owner identity; promotion must first verify/repoint the production JSA Scope to `KIT JSA` through a governed write. |
| Exact Friday-ticket census unavailable | DATA/CONFIG / EXTERNAL BLOCKER | Linear connector reads all returned `UNAUTHORIZED`, `oauth_token_invalid_grant`, `TRIGGER_REAUTHENTICATION`; the protected production debug endpoint returned 401 without a Signal session. | Reauthenticate Linear and rerun the read-only census before promotion. No titles were guessed. |
| Work links did not affect Forecast | PRODUCT BUG | Forecast inputs always contained every current Linear issue, independent of accepted Capability status or CapabilityWorkLink. Moving shape in/out was cosmetic to delivery. | Once canonical capabilities exist, accepted active links define modeled execution; outside/future links remain claimed but excluded. |
| Execution work without product shape was hard to place | UX GAP | There was no direct, reviewable bridge from raw Linear identity to a capability. | `NO CAPABILITY YET` tray, drag onto accepted capability, deterministic impact preview, explicit commit. |
| Concurrent browser edits could silently replace each other | PRODUCT BUG | Capability had no optimistic revision token or idempotent mutation receipt. | Revision increments, stale-write 409, unique idempotency keys, serializable transaction retry, append-only events. |
| Owner change required operators to visit downstream screens | PRODUCT BUG | Browser-local shape never invalidated server derived state. Some other owner routes already did. | Every governed capability and Scope configuration write invalidates and eagerly recomputes the shared derived receipt. |

No evidence indicated that localStorage, sessionStorage, IndexedDB, or TanStack Query stored accepted Scope. localStorage is limited to private Control Room workspace lenses. The defect was the older module-level Scenario/draft store being presented too much like Reality.
