# Continuous improvement after activation

## Loop

```text
new transcript / source change
  → Hermes knowledge compiler
  → immutable source artifact + exact evidence passages
  → structured intelligence/current-state heads + longitudinal relations
  → derivative wiki synthesis update
  → gaps/opportunities projection
  → Project Knowledge Refresh Package
  → Signal stores immutable package and compares fingerprints
  → Audit sees new external evidence/intelligence
  → review tray opens only where delivery Reality could change
  → human acceptance writes the appropriate canonical owner
  → Forecast/Timeline/Reports re-read Reality
```

Activation does not copy knowledge into a disconnected Signal fork. The Scope retains its compiler project/entity id, accepted aliases, source registrations, and package lineage. Future scans query the same knowledge graph and emit deltas against the last package.

## Refresh classes

### Context-only

New evidence/intelligence/wiki synthesis with no proposed delivery change. It can update the latest immutable ContextSnapshot and Audit/search projections, but does not open a governance tray unless policy requires snapshot acceptance.

### Candidate change

New or materially changed capability, Decision, dependency, milestone, source registration, owner, or operator-assertion contradiction. Opens review; no Reality effect.

### Currentness/supersession

An intelligence head changes, a source becomes stale/unavailable, or an object is superseded/resolved. Signal shows the external update and may open a review item if canonical Reality now conflicts. It never mutates the canonical object automatically.

### Execution truth change

Linear changes remain directly owned by Linear and flow through existing reads. Hermes may contextualize them but does not duplicate them into package truth.

## Disposition memory

- stable candidate key + unchanged fingerprint inherits prior disposition;
- accepted candidate resolves to its canonical object and does not reappear as new;
- rejected candidate stays rejected while evidence/meaning is unchanged;
- deferred candidate remains deferred and shows new currentness;
- information-only candidate remains searchable;
- materially changed evidence fingerprint resurfaces the item with its prior history and a diff;
- merged candidate routes new evidence to the survivor review record.

The fingerprint includes normalized typed payload plus sorted raw lineage roots. Cosmetic wiki wording does not reopen a rejected item; genuinely independent new evidence can.

## Ongoing governance

Every owner keeps its own acceptance boundary:

- Capability/Scope changes → Scope review;
- Decision changes → Decisions;
- serial constraint → explicit DecisionGate review;
- cross-project prerequisite → Dependency review;
- accepted plan/commitment → Timeline;
- source tracking policy → SourceRegistration;
- staffing/capacity → Portfolio;
- execution work → Linear.

Hermes can recommend the destination, but it cannot bypass the destination’s validation or write path.

## Refresh package minimums

- `scopeId` and compiler project identity;
- package id/version/compiler version/generated time;
- source coverage with observed-at timestamps;
- new/changed/tombstoned artifacts and passages;
- current intelligence heads and changed relations;
- candidate deltas with fingerprints and previous keys;
- contradiction and ambiguity deltas;
- raw lineage roots;
- warnings and provider failures.

Signal must be able to rebuild the current search/graph projections from immutable snapshots plus canonical state. No wiki page is the only copy of provenance.

## Audit cadence

- immediate first Audit at activation;
- event-driven structural Audit after accepted Reality changes;
- evidence-only Audit after materially new knowledge, with human acceptance still required for Reality changes;
- scheduled staleness/coverage checks later, without automatic canonical mutation.

## Reports

Reports can say:

- new knowledge received since the last report;
- review items pending;
- canonical changes accepted;
- provider/source health changed;
- Forecast effects caused by canonical changes.

They must not describe a candidate as shipped, planned, committed, staffed, or blocking until its canonical owner says so.

## Retention

- raw sources and evidence passages remain immutable under their source retention policy;
- wiki synthesis may change but every revision points to lineage roots;
- ContextSnapshots and bootstrap packages are immutable;
- candidate dispositions are append/audit history, not hard-deleted;
- vector indexes are derived and rebuildable;
- canonical objects use explicit retire/supersede/resolve states.
