# Audit World implementation guardrail

## Acceptance rule

The simplified Audit imagery in the Signal Visual System prototypes is a
**material and widget demonstration only**. It is not a replacement design,
spatial specification, or acceptance reference for the Audit World.

The implementation formula is:

> **Same Audit World + Signal visual language**

It is not:

> New Audit World designed from the visual-system mockup

## Protected spatial instrument

The current real Rubric-powered production Audit World is the acceptance
reference. Visual-system implementation must not modify, simplify, redraw,
reinterpret, or replace:

- actual Rubric world geometry
- Rings, Circle, Force, or Hex
- Project World density
- Source Systems horizon
- Attention structure
- Reality / Project Model composition
- fog or haze
- node placement
- camera
- drag physics
- morphs
- progressive identity
- relationship topology

This protection applies even when a simplified prototype appears easier to
implement. Prototype geometry is illustrative scaffolding only and carries no
product authority.

## Allowed visual-system surface

The Visual System may change:

- widget material
- shell and chrome
- Inspector material
- Search material
- Legend, Menu, and control styling
- typography
- semantic color mapping
- hover, selected, and focus treatment where truth semantics remain intact
- shared Signal tokens

These changes wrap or style the production world. They do not change the
world’s spatial authority, behavior, density, relationships, or disclosure.

## Reality glyph ownership

The `Signal Core` shown or described in this package is conceptual only. The
dedicated Reality Glyph exploration branch owns the final center-glyph
decision. This branch must not implement, ship, or establish a competing
center glyph.

Until that branch resolves the glyph, preserve the production Audit center
identity and accessible name.

## Implementation acceptance checks

An Audit visual-system change is acceptable only when:

1. A before/after comparison confirms identical world geometry, density,
   topology, placement, camera framing, and progressive disclosure for the
   same data and viewport.
2. Rings/Circle/Force/Hex, drag, camera, morph, Trace, fog/haze, and progressive
   identity behavior pass their existing production acceptance checks.
3. Changed files are limited to shared tokens, shell, and permitted widget or
   interaction treatments unless the protected-world owner explicitly
   approves otherwise.
4. Any hover/selected/focus change preserves the existing truth, trust, and
   attention semantics.
5. No center-glyph change is included.

When a proposed styling change requires protected spatial code to achieve its
look, stop and redesign the styling change around the production world.
